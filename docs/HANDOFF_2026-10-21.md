## 验证结果及其边界

### 真实勾画闭环

使用独立测试数据库、独立项目目录和真实百度 OCR、配置的文本模型、MiniMax 音频及离线 Qwen 定位，执行正式路由：

`OCR → AI 推荐 → Qwen 定位 → 空间复核 → 同步预览 → 确认 → 正式 MP4 → 下载与抽帧`

横屏、竖屏均完成。两页原始建议都包含需要复核的次要零散目标；确认接口以 HTTP 422 `review_required` 阻止直接确认。查看原图并删除不合适目标后，保留完整“核心概念”，预览与正式构建一致，视频任务成功、错误字段清空、产物登记存在。

这属于真实供应商与正式 API 闭环，包含 Agent 空间复核，不是无人复核自动验收，也不是整条真实浏览器鼠标操作验收。后续连续性修复重放同一保存结果，两页建议均从 2 条降为 1 条；它只证明已知零散建议被过滤，不能外推复杂页面的语义准确率。

Qwen 两条真实定位耗时约 83.19 秒、57.85 秒。30fps 帧调度相对模型时间的误差为 +26.67ms、+6.67ms；成片音轨互相关偏移约 +42.69ms。这些只验证工程时间传递，不能替代真实发音人工标签。独立听音验收继续标记待验收，不重复要求用户立即标注。

### Mask 与勾画精准度排查

当前代码对冻结的 12 张页面回放，12/12 满足内部检测前景像素约束，保存 Mask 跨组重叠为 0。与既有 AI 矩形草案的宏平均 IoU 从旧回放约 71.44% 到 82.03%，7 页改善。该草案不是人工真值，不能称为“准确率 82.03%”；没有重新调用供应商或重新检测，也不能冒充全新 A/B。

生产函数探针确认的剩余风险：固定标题区域可覆盖正确模型归属；连续 OCR 字符不保证语义对应或空间接近；Prompt 缺少局部空间上下文；高亮路径尚缺完整的邻词边界约束。详细证据、限制和验收设计见 [精准度专项排查](annotation-validation/precision-audit-2026-10-21.md)。这些是后续计划，本轮没有实现。

## 后续开发顺序

| 优先级 | 工作 | 完成标准 |
| --- | --- | --- |
| P1 | 修正 Mask 标题定位和规则优先级 | 契约/OCR/视觉证据识别真实标题，固定高度仅作条件先验；覆盖横竖屏与中部标题，不能破坏前景覆盖、零重叠或手工修正 |
| P1 | 勾画短语候选与语义、空间校验 | 为候选提供必要文本和局部上下文；识别“连续但选错词”及超远间距；保持真实 ID/字框，不自动拼凑未选字符 |
| P2 | 有界冲突复核与高风险 OCR | 只复核错组风险、大块补全和歧义区域；实际比较高精度 OCR 的收益、延迟和调用成本，再决定切换范围 |
| P2 | 高亮笔迹邻词边界 | 补齐最终栅格的横向、跨行和小字间距约束，抽帧验收，不能只以几何参数通过为完成 |
| P3 | 恢复人工听音验收后再调时序 | 按音频哈希匹配独立人工起点，统计误差分布和失败样本；在用户恢复验收前保持待验收 |

建议先实现两个 P1，逐项隔离回归，再用新增真实页面验证。准备 30–50 页横竖屏、不同标题位置和卡片布局，区分开发集与未见验收集；这是首轮工程样本建议，不是统计准确率保证。分别统计目标归属、语义正确性、人工修正量/耗时、延迟和请求量，不将覆盖率等同于可用率。
