## 当前协议

Agent API **3.0.0**。`digital_human.generate` 从原来的错误逐页循环和 `results` 包装改为复用 `digital_human_routes.generate_dh_full`，返回真实 `job_id/status`，并传播真实失败。该返回行为变化按破坏性契约升级处理，不保留旧结果别名。客户端必须刷新发现文档与精确能力 revision。

`image.candidate.apply` 的 `payload.regions` 为 1–20 个 `[left, top, right, bottom]` 原画布整数矩形；使用区域时必须提供 `expected_image_sha256` 和 `expected_candidate_sha256`。范围外像素不变；来源记录保留基图哈希、候选哈希及区域。它沿用单页 `slide_image_changed` 失效，不重做无关音频。

数字人新增可恢复状态 `waiting_external`：客户端继续查询原 job，不重新提交。只有已记录的确切引擎 ID 才能自动取回结果。下载写入独立暂存文件并验证可解码后发布；单纯客户端超时不是服务端取消。

整段语音来源记录位于 `planning/digital_human/audio_full.source.json`，绑定当前页面顺序、逐页音频哈希、间隔及输出哈希。旧记录缺失或不匹配时必须重新导出，不能直接生成整段数字人。进程内回滚不等同于跨文件、跨数据库的断电事务保证。

## 批量图片修复

运行 `python scripts/batch_image_repairs.py --manifest INPUT.json --report REPORT.json --review-manifest REVIEW.json --base-url http://127.0.0.1:8000`。输入包含 `project_id`、明确的 `batch_id` 和 `slides`，每页含 `slide_id`、完整 `prompt`，可附带修复 `regions`。该阶段只生成候选。

检查候选后，在 REVIEW.json 中补齐矩形并将通过复核的页面设置 `reviewed: true`，再运行相同脚本并加 `--apply-reviewed`。未复核页面不应用。生成续查固定幂等键及 revision；应用响应未知时停止并检查当前图片，不自动重放。报告只保存服务/身份上下文指纹，不保存 API 密钥。

## 代码复核

按 code-review-and-quality 的五个维度复核：正确性包含失败回滚、CAS、原任务续查和同值保存；可读性将纯像素与音频导出规则放在独立模块；架构保持源业务服务与 Agent 适配一致；安全性检查账号归属、密钥导出确认、报告无密钥及路径边界；性能检查媒体探测超时、任务数量上限和共享网关治理。测试中使用会话临时数据目录，真实演练使用独立数据库及素材目录。

生成文字仍须按具体画面复核。本批提供局部修复与 OCR 置信度提示，不能把“模型请求成功”视为每个汉字都正确。规划目标时长与实际音频长度也分别记录，不通过拉伸音频伪造目标达成。
