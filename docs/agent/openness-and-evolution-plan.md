# Agent 全功能开放与持续演进规范（提案）

日期：2026-10-23。状态：规划草案，尚未代表实现或发布承诺。按用户补充约束修订：不兼容历史 Agent 规范，不承担旧项目迁移；以新规范统一当前实现。详细执行拆分见 `development-plan.md`。

## 1. 目标和边界

Agent 是与 Web UI 并列的正式客户端。所有有业务意义的用户操作，默认具备可发现、可调用、可验证、可恢复的 Agent 能力；纯展示行为不必暴露。新增功能与 Agent 支持在同一变更中交付。

本次可直接调整旧接口、字段和工具定义，不建设历史适配层。新规范建立后，Agent 通过实时发现使用当前能力；运行中的请求绑定契约版本，不匹配时明确拒绝并刷新，不能静默误执行。未来是否支持固定旧客户端是另行决策，不是本期要求。

开放业务能力不等于开放任意 Python 执行、SQL、文件路径写入或密钥读取。以账号权限、资源归属和业务服务验证作为共同边界。

## 3. 架构规范

```text
Web UI ── Web routes ───────────┐
                               ├── source-owned services ── stores/jobs/artifacts
Agent ── MCP / CLI / HTTP ──────┘
          ↑
统一能力注册表 + 请求/响应模型 + 工作流规则 + 权限规则
          ↓
发现文档 / OpenAPI / 工具定义 / 文档 / 契约测试
```

继续使用现有模块边界。Agent 适配层复用业务服务，不复制算法，不经浏览器调用，不通过完整 server 模块访问业务。既有 Web 路由不必迁入 Agent 路由，但二者遵循相同验证、失效传播和提交规则。

注册表负责对外契约，业务模块负责行为。生成工具定义和文档，不盲目生成业务实现。现有 `agent_api/routes.py` 后续按领域拆分，避免形成新的单体。

## 4. 开放范围

对每项业务功能登记一个稳定 feature ID，以及暴露状态、对应 capability IDs、责任模块、验收场景；豁免必须包含理由、负责人和复查条件。不得将未完成支持标为“UI 专属”来规避检查。

| 领域 | 目标能力范围 |
|---|---|
| 项目与课程 | 项目 CRUD、课程/章节管理、归属、画布、生产模式、配置包 |
| Step 1 准备文章 | 内容读取、导入、编辑、主题生成、生成参数与 Prompt |
| Step 2 内容规划 | 生成/读取/编辑、页面增删排序、旁白映射、契约验证、模板和 Prompt |
| Step 3 图片 | 风格/参考图/IP、生成/上传、批量操作、候选选择、排序、确认、预览 |
| Step 4 Mask | 自动识别、状态、分组、精确 Mask、人工修正数据、动画参数、预览和确认 |
| Step 5 旁白与音频 | 旁白、TTS 标记、声音参数、生成/重试、播放资源、字幕、音频确认 |
| Step 6 勾画标注 | 启用决策、OCR、规划、编辑操作、时间线、预览和确认 |
| 可选 Step 7 数字人 | 配置、健康检查、任务创建/查询、资源与错误恢复 |
| Step 8 输出作品 | 渲染、PPTX、字幕导出、任务查询、产物获取/删除、变速版本 |
| 横向能力 | 配置、模板、身份、权限、诊断、日志、操作停止、批量任务、审查决策 |

表中是目标覆盖清单，不能据此认定均已实现。可视编辑需提供结构化等效操作和预览产物，不要求 Agent 模拟鼠标。

## 5. 能力契约

扩展现有 AgentCapability，每项能力必须描述：

- 身份：稳定 ID、版本、生命周期、说明、替代能力、废弃时间。
- 数据：输入/输出 Schema、字段含义、单位、默认值、限制、示例；避免无约束的对象作为核心结果。
- 执行：权限、前置条件、副作用、下游失效影响、幂等规则、并发冲突规则、长任务行为。
- 恢复：错误码、是否允许重试、退避建议、修复动作、是否需要用户决策。
- 交付：业务服务映射、HTTP/MCP/CLI 支持方式、契约场景及责任模块。

所有新增字段采用明确的模型校验；动态字段须声明扩展区。路径、查询和请求体字段由统一 Schema 生成器准确组合。

新增业务能力默认同时开放 HTTP、MCP 和 CLI 的等效操作。二进制与事件流可通过资源或下载地址等效提供，无需强行包装成普通工具返回值。

## 6. 动态发现和工作流

以现有 `/api/agent/v1/meta` 为入口，补充服务实例/构建标识、支持的版本范围、能力目录版本；支持按领域/关键词检索和读取单项契约，避免把全部工具详情塞进上下文。

分别回答三个问题：服务支持什么；当前身份有权做什么；当前项目此刻能做什么。身份或运行状态变化不应改变静态契约哈希。

项目状态应返回 revision、稳定阶段 ID、前置条件、阻塞项、允许动作和下一步建议。使用 `storyboard`、`images` 等语义 ID；用户可见 Step 编号仅用于展示，内部阶段映射由服务端管理。数字人禁用不阻塞输出，标注按保存的决策状态判断。

新增项目级变更预检能力，返回预计失效产物、受影响页面、需要重新确认的阶段。预检不是锁，实际提交仍校验 revision。任何确认绑定具体资源版本，避免内容已修改却批准旧结果。

客户端在连接、重连、服务构建变化、契约变化时刷新。哈希变化触发差异检查，不直接等同于不兼容。缓存须有有效期或重新验证机制。

MCP 保留常用明确工具；增加能力搜索、详情读取和受控通用调用，作为工具目录无法即时刷新的客户端的后备入口。通用调用只允许注册能力，复用完全相同的权限、Schema 和审计，不接受任意内部函数名。

## 7. 写入、并发和长任务

- 可重试写入声明幂等键：作用域至少包含身份、能力和目标资源；相同键不同载荷返回冲突。声明保存期限，超期后不得承诺重复提交仍不产生副作用。
- 编辑采用资源 revision / expected_revision，冲突时返回当前版本及可执行的重读动作。
- 长任务返回稳定 operation_id，通过该 ID 查询，不依赖 latest 定位并发任务。
- 任务状态、结果、错误和产物持久化。进程退出区分 interrupted 与 failed；恢复能力按任务类型明确声明。
- 取消请求返回已请求状态，只有实际安全停止后才进入 cancelled。保留现有精确 operation ID 协作停止机制，不将客户端断连当取消。
- 事件支持游标与断线补读；事件丢失时可回退轮询。未实现补读前明确限制，不能宣称可靠事件恢复。
- 批量操作返回逐项结果；默认不承诺跨外部生成请求事务原子性。
- 产物返回资源 ID、类型、内容哈希、来源版本和获取方法；大文件不塞入普通 JSON。

错误统一包含 code、message、details，并逐步增加 retryable、retry_after、repair_actions 和 trace_id。用户输入错误、版本不匹配、资源冲突和供应商故障必须可区分；未识别的任务状态不能静默当作成功。

## 8. 当前契约与发布

新规范覆盖替换现有 Agent 规范，HTTP、MCP、CLI 和文档同批更新，不保留旧字段别名、旧协议路由或迁移窗口。版本和契约快照用于识别变化、同步发布与避免旧上下文误调用，不用于支持旧规范。

| 变化 | 默认处理 |
|---|---|
| 新能力、带默认值的可选输入 | 更新能力目录和契约快照，验证动态发现 |
| 新输出字段 | 更新模型、消费端和场景断言 |
| 新枚举值、默认值变化 | 更新描述和行为测试，刷新对应契约指纹 |
| 字段删除/改名/变必填/类型收窄 | 同步替换所有受控消费端；过期请求拒绝后重新发现 |
| 权限、工作流、副作用、失效规则变化 | 更新行为版本、影响声明和场景测试 |

未来发布默认只提供当前契约；不得要求 Agent 从缓存知识推断新参数。需要升级发现协议本身时，明确返回客户端升级要求，不能承诺任意旧客户端自动适配。

能力发现与通用调用构成小而稳定的入口。动态客户端可在此入口内获取新业务能力；只有该入口或传输协议变化才需要客户端升级。

## 9. 强制同步门禁

将以下检查接入现有 `scripts/run_checks.py`，由当前 CI 统一执行，避免另设一套检查入口：

1. 功能目录覆盖：业务路由通过 `route_inventory.py` 盘点，所有业务功能有暴露映射或有理由的豁免；后台任务和无路由业务还需功能目录补充。
2. 字段覆盖：从现有项目字段映射扩展到各领域的输入、输出及配置。
3. 传输一致：注册表、Agent API、OpenAPI、MCP、CLI、文档一致；保留已有双向断言。
4. 变更同步：Schema 差异检测、行为版本与契约快照检查、过期契约拒绝与重新发现。
5. 行为场景：编辑导致何种失效、过期确认拒绝、动态调用任务、幂等重试、并发冲突、重启恢复、权限隔离。
6. 生成文件：能力矩阵、契约快照和示例与源码一致。

路由覆盖不能证明完整开放，Schema 一致也不能证明行为兼容；两者必须与端到端场景配合。测试使用现有隔离数据库和 runs 目录，默认模拟付费供应商，禁止修改真实用户数据。

功能交付定义：业务实现 + Agent 契约/适配 + 发现信息 + 契约变更评估 + 测试 + 文档，同一变更完成。纯样式变更可记录无 Agent 影响；不能靠提交说明里的勾选框代替自动检查。

后续实施时将这一交付定义加入 AGENTS.md 和 PR 模板；本提案尚不直接修改现行强制规则。

## 10. 实施顺序和验收

| 阶段 | 交付物 | 验收条件 |
|---|---|---|
| A 建立基线 | 全功能目录、暴露差距、当前契约快照、CI 门禁 | 新业务入口未登记会失败；契约变化可比较 |
| B 可靠交互 | 项目动作发现、revision、统一任务寻址、预检和恢复信息 | Agent 可识别阻塞、处理冲突、查询准确任务 |
| C 完整覆盖 | 按八步和横向配置补齐操作 | 每项范围功能有能力及场景，或可审计豁免 |
| D 动态演进 | 能力搜索/调用、缓存刷新、统一发布 | 服务新增能力后动态客户端无需改代码即可发现调用；过期请求不会静默误执行 |

优先做 A，再补 Step 2 编辑、Step 3 风格/上传、Mask、标注、PPTX 等矩阵未完整表达的细粒度能力。B 与各领域补齐结合实施，不一次性重写所有接口。

最终验收用例：Agent 创建项目、导入文章、规划、编辑单页、生成/替换图片、修正 Mask、编辑旁白和生成确认音频、决定并编辑标注、跳过数字人、导出视频和 PPTX、下载产物；期间插入超时重试、内容冲突、进程重启和契约更新，均得到明确结果或可执行恢复步骤。

目标指标：业务功能登记覆盖率 100%；约定范围无理由缺失数为 0；稳定能力均具备契约和行为场景；契约变更未同步时发布失败；动态客户端黄金任务通过。运行环境和上游故障不承诺消失，但必须可识别、可恢复。
