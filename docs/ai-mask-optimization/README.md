# AI Mask 优化实施与验证方案

日期：2026-09-19。交付范围：方案、8 张可复现标准图、精确分组答案、1 张生成式压力图、评分工具与检测基线。**尚未修改生产算法，也未验证完整多模态标注效果。**

## 1. 决策与目标

保留一次生成整页、纯白外背景、文字与所属底板同步出现、原图像素和原始位置不变的路线。优化目标是“按旁白准确归属可见内容”，不是恢复被遮挡的独立素材。默认轻量 CPU 检测与 OCR；当前配置的视觉模型负责语义判断（若通过 API 使用，客户端无需 GPU，但并不等于全离线）。完全离线可保留 OCR、几何分割与手动修正，不能承诺同等自动语义能力。

当前仓库仍支持可配置视频背景，默认值与本次用户的纯白项目设置并非同一概念。实验必须显式使用 #FFFFFF；不能为了本实验更改全局默认或破坏其他背景项目。生产路径继续遵守精确 RLE、零组间重叠、保留封闭白区、手动修正保护和原图不得充当已标注页背景的契约。

推荐目标流程：原始像素与多尺度候选 → OCR / 容器关系 → 视觉模型分组或请求局部拆分 → 局部分界 → 像素归属冲突解决 → RLE → 实际 Reveal 渲染验证。不要一上来引入大型 SAM，更不要把整个系统重写后才验证。

## 2. 已核实的问题及本次证据

1. `ai_mask_component_detection.py` 在检测连通组件前使用默认半径 6 的全图闭运算，会把原本分离的近邻区域粘连。
2. 同模块以“不能从边界洪泛到达”定义前景，封闭大边框会把内部白区和卡片连接为整体。不能简单改成所有白像素都是背景，否则封闭内容白区又会被损坏。
3. `_apply_layout_binding` 依据中心点聚合整个组件，不负责把组件内部切开。DocLayout 候选框应作为证据，而不是无条件归属规则。
4. `ai_mask_semantic_matcher.py` 先截取最多 120 个对象，再按距离聚类到最多 min(12, beats+3) 个。模型输入又要求聚类对象整体归属，复杂页可能在语义判断前失去粒度。
5. 候选 `ocr_text` 为空；文字识别没有成为稳定的定位证据。
6. 默认 245 白阈值可能丢失浅灰底板、阴影和文字抗锯齿。覆盖率应有独立原图参照，不能只用检测器输出作为分母。

### 本机检测实验

报告在 `validation/baseline_r6/report.json` 和 `validation/baseline_r0/report.json`，环境和单次时间在各自 `timings.json`。仅运行纯检测器，**没有 DocLayout、OCR、视觉 API、对象聚类、渲染或峰值内存测量**。

为隔离检测缺陷，实验用标准答案给每个组件选择重叠像素最多的讲解组。这个 oracle 只对固定组件做最有利的正确像素分配，并非对宏 IoU 求全局最优；不能把结果当作完整 AI 准确率，也不能用这套有答案的分配器作为新算法。

| 场景 | 默认 r=6 宏 IoU | r=0 宏 IoU | 结论 |
| --- | ---: | ---: | --- |
| 独立卡片 | 0.9982 | 0.9901 | 取消闭运算后仍要恢复文字边缘 |
| 8px 间隔 | 0.3315 | 0.9901 | 默认粘连造成明显误合并 |
| 2px 间隔 | 0.3315 | 0.9901 | 同上 |
| 箭头连接 | 0.9975 | 0.9895 | 此图现有投影拆分有效，不能声称所有箭头都失败 |
| 浅灰卡片 | 0.3420 | 0.3144 | 阈值造成大量浅色内容丢失 |
| 15 个正文组 | 0.9995 | 0.9975 | 检测可分；本实验没有覆盖后续 12 对象聚类限制 |
| 公共外框 | 0.1635 | 0.1608 | 关闭闭运算不能解决封闭白区混合 |
| 分离文字和图标 | 0.9960 | 0.9777 | 几何分离不代表语义独立；需 OCR 和语义分组 |

单次冷缓存纯检测约 2.9–3.7 秒/页，仅代表本机和这批合成图。r=0 仍全部未达严格逐组门槛，其中一些由标题细小抗锯齿丢失导致；不能只报告平均 IoU 来掩盖它们。

## 3. 实施阶段与通过条件

### P0：固定基线、数据和可观测性

- 固定输入图 SHA256、旁白、组 ID、模型版本、有效设置和 Prompt 版本；输出算法版本、缓存键、回退原因。
- 每页记录 load / detection / OCR / semantic / refinement / apply / render 各阶段耗时；记录网络重试与等待时间。
- 新检测算法用项目级实验开关，旧路径可回退；算法版本进入缓存键。不得复用旧版本检测缓存。
- 增加真实失败页，建议至少 30 页：20 页用于调参，10 页冻结盲测。近似变体不得分散到训练和盲测两侧。
- 通过条件：交付评分器自检通过，基线可复跑，数据不触及用户真实项目写入。

### P1：保留细粒度证据，避免过早合并

落点：`ai_mask_component_detection.py`、`ai_mask_semantic_matcher.py`、对应 checks。

- 检测输出保留原始组件；闭运算结果仅作分组候选。多尺度 r=0/2/6 可作对照，不能把三套结果都当成独立像素所有者。
- 移除以对象数量为目标的强制几何合并。保存父候选与子组件引用，用分页/分区域请求控制模型输入量；超限必须报告，不能静默丢弃。
- 同一文字行或卡片的逻辑归组，不要求其像素连通。OCR 未接入前也必须保留拆回原始组件的能力。
- 加入两阈值证据：高可信内容种子、疑似浅色支持区域。种子向支持区域有限扩展，并受容器和其他组边界限制。参数需在固定集扫描，不直接把新阈值写死为“最优”。
- 通过条件：2px/8px 间隔组不误合并；标题边缘不因关闭闭运算退化；增加 >120 候选单测验证不丢候选。

### P2：OCR 与容器层级

新增职责清晰的 `ai_mask_ocr.py`（CPU 模型生命周期、文字多边形和文本）及 `ai_mask_regions.py`（容器/候选层级）。通过窄依赖接入，路径来自 `repository_paths.py`。

- 优先评估 RapidOCR 的 ONNX CPU 路径，固定模型文件摘要；本方案没有安装或测过 OCR 模型。
- 输出文字内容、四边形、识别置信度。原图坐标是唯一坐标基准；任何缩放/裁剪保存可逆变换。
- 文字匹配旁白只是证据，同名标题和重复标签要结合位置与全文；OCR 不准确时保留原图视觉判断，不强行匹配。
- 建立“页面 → 公共边框 → 卡片 → 标题/文字/图标”关系。封闭大外框是容器候选，不能因其包围区域不可洪泛就把全部子对象合为前景组件。
- 白色区域需要区分外部背景、对象内部白色和容器间隙；语义容器为后两者提供上下文。公共底板若遮住原本看不见的内容，不进行无依据恢复。
- 通过条件：公共外框能与内部卡片独立归属；分离文字与图标正确同组；同名字不同卡片不串组。

### P3：语义匹配支持局部拆分

落点：`ai_mask_semantic_matcher.py`、Prompt 配置所有者；改 Prompt 时按仓库 optimize-prompts 技能审计真实输入输出。

模型输入只包含原图、需要的局部裁剪、稳定候选 ID、OCR 与当前旁白组。让模型返回三类操作：

```json
{
  "assignments": [{"group_id": "g_02", "candidate_ids": ["c_07", "c_08"], "evidence_text_ids": ["t_03"]}],
  "split_requests": [{"candidate_id": "c_12", "targets": [
    {"group_id": "g_03", "seed_xy": [850, 420]},
    {"group_id": "g_04", "seed_xy": [1180, 420]}
  ], "reason": "两个独立卡片"}],
  "unresolved_group_ids": []
}
```

这是待实施的内部协议，不是现有 API。校验 ID 存在、坐标范围、冲突、空分配和目标数。模型坐标仅作为线索，不能直接作为最终像素归属。对不确定点在局部裁剪中二次定位；每页最多两轮修正，超过则标注需复核，避免循环请求。

- 大页先按区域分页，再在合并阶段处理跨区域对象；原始候选 ID 始终保留。
- 所有候选先完整保留，只有足够证据才合并。低置信度残片不能无条件就近吸收。
- 通过条件：15 正文组加标题均可匹配；“一个候选里两张卡片”能触发局部拆分；模型错误输出不破坏现有已确认 Mask。

### P4：CPU 局部边界与像素归属

建议新增 `ai_mask_region_refinement.py`，保持检测、语义匹配、Manifest 写入和 Reveal 渲染职责独立。

1. 分离模块：沿高可信白色通道找边界，允许多边形与多个不连通区域。不能只用矩形全框。
2. 疑似粘连：回到未经形态学修改的原图组件。结合 OCR/容器种子，用局部边缘代价搜索或标记分水岭比较候选切法。
3. 连线与箭头：在数据标注中明确归属。本套图箭头归左侧/来源组，这是测试约定而非通用真理。
4. 文字和底板一起出现：容器内部整体保留，不逐字抠空。
5. 多候选争抢像素：以边界证据、容器、文字匹配联合决策，不按处理顺序先到先得；没有可靠解则进入复核。
6. 大多数页面不引入 SAM。仅当真实盲测证明规则边界仍是主要瓶颈，才评估 MobileSAM 作为可选局部分支，复用图像编码且记录额外耗时。

最终只产生一套互斥像素归属，再编码 RLE。手工笔画、锁定/确认状态仍由现有机制保护；生成输出不得直接写入未备份的真实项目。

### P5：渲染、交互与发布

- 完整合成后与原图逐像素比对；同时导出每一步揭示截图，检查是否提前带出邻组或漏掉文字。
- 白底允许局部边界宽松，但渲染仍必须防止白矩形覆盖已出现的组。测试淡入、缩放、位移等实际启用动画，不能仅检查静态叠加。
- 维持源码像素颜色与坐标、封闭白区、浅灰阴影和中文细线；边缘去白改动必须同时测 #FFFFFF 与现有其他背景项目。
- 复核界面优先支持：拆分区域、合并区域、指认归属、单组播放。保留现有画笔作为兜底。
- 先单项目实验，再对比批处理，最后才默认启用。算法版本变化触发缓存/下游资产重建；旁白变化只重跑依赖旁白的阶段，不必重算图像 OCR。
- 新增设置/服务字段若对 Agent 可见，按 AGENTS.md 更新能力注册、模型映射、版本与生成文档。发布前运行 AGENTS.md 完整必需验证；本次仅交付离线实验，不是生产发布。

## 4. 测试图片与答案

`validation/contact_sheet.png` 是总览。`validation/cases/<case>/image.png` 均为 1920×1080 RGB、纯白外背景、底部字幕留白。

每个目录包含：`groups.json`（组 ID、旁白及策略）、`labels.png`（16 位所有权标签，0=白背景）、`group_001.png` 等（L 模式、0/255 二值标准 Mask）。标题为 group_001；正文顺序对应后续组。公共边框归标题；箭头归来源组。标准答案由独立绘制层得到，不由待测算法生成。

这些图测试几何与像素边界，不足以代表复杂插画分布。原图文字有抗锯齿，但色块边界相对规整；真实样本仍必需。`labels.png` 直接看可能近乎黑色，是标签数据而非彩色预览。

`validation/manual_review.csv` 提供人工复核、修正时间、端到端耗时和内存记录空表；空项表示尚未测量，不能填成零。每个算法/重复轮次复制对应行，真实盲测页另加行。

生成式压力图：`validation/realistic/generated_stress.png`，期望 7 组：标题、采集、清洗、分析、建模、验证、决策。上下两行分别从左到右讲解；行内箭头归来源卡片。卡片内文字、图形、底板和阴影一起出现。

**该生成图实际是 1672×941，外边界精确白像素比例约 11.96%，不满足严格纯白输入契约。** 保留原始文件，作为“生图未严格遵守白底要求”的域外压力样本，不能混入8张精确测试评分。应用正常上传规范化后另存测试副本，再人工确认边界；需要精确评分时必须两人独立审核实际上传后图像的标准 Mask，不能缩放原始答案冒充。它无精确答案，不能用于报告像素 IoU。

## 5. 直接运行验证

从仓库根目录打开 PowerShell，使用已安装 Pillow、NumPy 的 Python。无需启动服务器、数据库、GPU 或调用外部 API。

```powershell
python scripts/ai_mask_benchmark.py selftest --root docs/ai-mask-optimization/validation
python scripts/ai_mask_benchmark.py score --root docs/ai-mask-optimization/validation --output docs/ai-mask-optimization/validation/baseline_r6
```

第一条应显示 PASS；第二条应报告已知失败并返回退出码 1，这代表基线不达门槛，不是程序异常。

重新生成及复跑基线，请使用新的输出目录（工具拒绝覆盖已有基线）：

```powershell
python scripts/ai_mask_benchmark.py generate --root outputs/mask-validation-new
python scripts/ai_mask_benchmark.py baseline --root outputs/mask-validation-new --output outputs/mask-baseline-r6-new --radius 6
python scripts/ai_mask_benchmark.py baseline --root outputs/mask-validation-new --output outputs/mask-baseline-r0-new --radius 0
```

生成需要微软雅黑或 DejaVuSans。跨机器更换字体会改变像素，因此对比请直接使用交付的 PNG，并保留 SHA256。baseline 命令是诊断采集，成功采集即正常退出；CI 门禁使用 score 命令的退出码。

### 将真正 AI 标注结果接入评分

1. 新建专用测试项目；按 `groups.json` 建立一页的讲解组，先固定分组与旁白，再在图片步骤上传 `image.png`，运行 AI Mask。不要让 Step 2 自由重写测试分组，也不要使用真实业务项目。
2. 确認实际图片尺寸与原图一致，且没有被重新生成。记录项目、slide_id 和实际 Manifest 组 ID。对完整工作流只通过应用/API 操作，不导入 server 去修改数据库。
3. 新建映射 JSON，例如把测试 ID 对应到真实 Manifest ID：

```json
{"group_001":"actual_title_id","group_002":"actual_card_1_id","group_003":"actual_card_2_id","group_004":"actual_card_3_id"}
```

4. 以下例子中的运行路径、slide ID 和映射路径需要换成实际值：

```powershell
python scripts/ai_mask_export_benchmark.py --manifest "runs/TEST_RUN/reveal_manifest.json" --slide slide_001 --mapping "outputs/mask-map-01.json" --output "outputs/mask-vnext/01_separated"
```

5. 对八张图分别导出到对应 case 名称目录，最后执行：

```powershell
python scripts/ai_mask_benchmark.py score --root docs/ai-mask-optimization/validation --output outputs/mask-vnext
```

导出器只读 Manifest，不修改项目；仅支持 groups 中的 1920×1080 row_runs_v1 自动 RLE。带手工笔画会明确拒绝，因为需要生产栅格化器计算最终 Mask。重复/未知 ID、错误坐标会拒绝。缺组按全空计分，不会自动跳过。额外生成组必须先检查其像素并映射回约定讲解组，不能悄悄丢弃装饰组来提高分数。

若另写新算法，可直接输出同规格二值 PNG，无需先接入 UI。**待测算法不得读取 labels.png、group_*.png 或用答案选择模型输出。** groups.json 只提供讲解契约。

## 6. 指标与验收

自动 score 已实现：逐组 IoU/precision/recall、宏 IoU、独立标准前景覆盖率、前景重叠像素、浅色像素召回率、遗漏原图像素的 RGB MAE。精确白色不参与归属评分，因此不惩罚“包含额外空白”；白色遮挡风险需真实渲染检查。

| 指标 | 建议门槛 | 当前是否自动判断 |
| --- | --- | --- |
| 标准前景覆盖率 | 每图 ≥99.5% | 是 |
| 组间前景重叠 | 0 像素 | 是 |
| 每组 precision / recall | 均 ≥99% | 是 |
| 浅灰专项召回率 | 05_pale ≥98% | 输出数值，人工额外验收 |
| 完整 Reveal 与原图 MAE | 白底平均 ≤0.5/255，差值>8 的像素 ≤0.1%，同时人工检查文字 | 否，需要生产渲染 |
| 真实盲测一次通过率 | 初始目标 ≥90%，按页计且报告样本量 | 否，人工双评 |
| 人工修正时间 | 相比旧版中位数下降 ≥50% | 否 |

这些是建议的工程门槛，不是已经达到的性能承诺。宏 IoU 不得代替逐组门槛；浅色召回不单独约束所有抗锯齿像素，是为了避免把不可见差异放大成唯一目标。报告中的 missing_source_rgb_mae 只统计遗漏像素，**不是实际渲染 MAE**。

CPU 基准建议固定 Windows 机器、4 核/8线程及16GB内存等级，记录实际型号与电源模式，ONNX CPU 后端限制线程数。每页冷启动 3 次、热缓存 5 次，报告中位数/P95、峰值进程及子进程内存、全部阶段时间；8张图的P95只是初步指标，最终使用更大集合。计时顺序交错，避免两套算法并发争抢 CPU。

初始产品预算：本地检测+OCR+边界处理 P95 ≤10秒/页、额外峰值内存 ≤2GB；视觉 API 延迟、费用、重试单独报告，并记录用户端总耗时。缓存命中 ≤1秒作为目标。若实测不达标，应减少重复编码与请求、分页裁剪，不能用降低分组粒度掩盖耗时。

## 7. 消融与停止条件

按顺序比较：旧版完整标注 → 仅移除强制合并 → 加原始组件/边缘恢复 → 加 OCR/容器 → 加局部拆分。每次只改变一项，固定样本与旁白；视觉模型重复3次观察波动。使用相同模型、输入预算和缓存策略，同时保留旧版输出。

- 改善只出现在合成图、真实盲测无改善：暂停上线，补充真实失效类型。
- 覆盖率上升但误合并或提前出现增加：判定失败。
- 仍有不确定区域：产生复核状态，禁止为了99.5%覆盖率强行吞并。
- P1–P4 达到质量和CPU预算：先发布轻量路线，无需引入更大模型。
- 若需要学习式新模型，使用人工修正数据训练/微调应另立任务，先固定独立盲测集，不污染验收。

## 8. 开源参考

- [RapidOCR](https://github.com/RapidAI/RapidOCR)：中文 OCR 与 ONNX CPU 部署。
- [OpenCV 标记分水岭](https://docs.opencv.org/4.x/d3/db4/tutorial_py_watershed.html)：局部有种子分割；不理解旁白语义。
