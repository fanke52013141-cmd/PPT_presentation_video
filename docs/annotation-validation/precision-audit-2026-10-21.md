# AI Mask 与勾画精准度专项排查（2026-10-21）

结论：基础链路可以工作，精准度仍值得继续优化。优先解决可观测的目标归属和校验缺口，不需要先引入通用自主 Agent。两步的质量要分开衡量：Mask 的“覆盖完整”不等于“跟对讲稿组”；勾画的“选区连续、调度准时”不等于“选对重点、对上真实发音”。

本次是诊断，不修改生产算法、Prompt、配置或用户项目。执行了当前函数探针、冻结真实页面回放、相关回归，并核查既有真实供应商证据。人工听音精度验收继续按用户要求暂缓。

## 1. AI Mask：标题定位与版式规则优先级最高

### 已确认的问题

`ai_mask_assignment.py:441` 按全局 style token 的固定标题框缩放；`:507` 将固定框内组件重新归标题。`:420` 还用 `220/1080`、`930/1080` 的相对高度判断标题带和字幕带。这些是位置规则，并非对本页真实标题的识别。

生产函数探针：输入模型已经正确区分的“中段标题”和“上部正文”，执行标题整合后，标题变成上部正文，中段标题从该匹配中消失。后续补全可能再分配该组件，但不能恢复已丢失的正确语义保证。原有真实竖屏页也存在中部标题漏分证据。

当前回放的结构门还出现不一致：数张与 AI 草案几乎完全一致的页面被标题/字幕区域规则阻断；三张竖屏页面的 `semantic_quality_passed` 为 true，但草案 IoU 仅约 0.48、0.59、0.57，且仍有警告。这个字段只说明没有触发对应阻断条件，不能代表语义正确或自动审批通过。

### 建议

- 将真实标题候选定位作为主要证据：契约标题文本、OCR 文本、字体/版式信息与视觉模型定位交叉核对。
- 固定标题带降为有条件的先验，不再覆盖已有强证据。不能把“画面较上方”直接等同于“主标题”。
- 横屏/竖屏、顶部标题/中段标题、整组图解分别验收。共享外框按现有讲稿组和包含关系判断，不仅根据包围多个框就归标题。
- 字幕安全区仍需校验，但区分原始输入不符合模板与算法错分，分别给出可处理原因；不能为了降低复核数量直接放宽所有阻断。

验收：标题完整召回、正文误入标题比例、独立标题正确显现率；同时统计规则覆盖模型的次数和对错。保持既有无需副标题、逐组显示和像素唯一归属约束。

## 2. AI Mask：提高对象语义匹配，约束覆盖补全

### 已确认的问题

当前完整对象保留已经改善；剩余低分页在模型归属阶段就可能失配。`_ensure_narrated_group_anchors` 会为缺失组选择剩余的大视觉岛；`_complete_component_coverage` 最终按兼容区域和距离给剩余前景指定归属。它们能避免空组和漏像素，但大小、远近不能充分证明内容对应讲稿。

当前代码已记录 model/rule/completion 来源、补全不增加语义置信度、大组件强制补全等风险。这些保护应保留。模型自报 confidence 和几何质量门都不是经过人工校准的正确概率。

### 建议

- 分开对象发现与讲稿匹配：先确保标题、卡片、图标、箭头、边框构成完整可辨对象，再匹配已有讲稿组；不能把一个连通组件必然视作一个语义对象。
- 对容易混淆的多卡片页面，给模型必要的局部文字/父容器关系，并保留完整页和适量切片。不要无限增加切片数量；既有真实运行存在输入超限而退回规则的记录。
- 只对冲突对象、缺组、大块强制补全、模型与规则冲突执行一次有界复核；验证后再决定是否上线。复核失败保留风险标记，不通过重复采样挑一个好看的结果。
- 现有“所有前景有归属”要求不变；大对象不能仅靠最近距离就获得“语义已确认”。装饰也应挂到已有的合适讲稿组，没有明确依据则显示具体归属风险，不擅自新增讲稿组或静默丢弃像素。
- 更细检测/更强分割器只能改善切分，不能单独解决讲稿归属；应先测清错误来自对象边界还是匹配。

验收：完整卡片归属率、讲稿组缺失率、错组像素比例、大块补全后人工修正率。以画面和契约核验为准，不能只提高覆盖率。

## 3. 勾画：从散字候选提升到有上下文的短语候选

### 已确认的问题

`annotation_prompt_templates.py:156` 实际只向模型发送候选的 `token_id/text/granularity`。底层已有 `line_id`、真实字框、原始文本和纠正信息，组装时没有提供行/卡片上下文。

探针将两个字从相邻位置改为相距 800px、不同卡片/行，模型收到的 user payload 完全一样。模型无法用未提供的信息区分这两种版式。既有上下文 A/B 的重复词合成压力样例从 4/8 提升到 7/8，同时有一次失败；4 条同一真实页的唯一词控制均为 4/4。它支持继续研究必要上下文，尚不足以证明上线收益或真实总体准确率。

### 建议

- 程序先生成连续词组候选，保留回溯到真实 OCR token 的映射。模型优先选完整词组，少做从散字拼词的工作。
- 提供必要的行/卡片身份和短上下文；同词多处出现时提供各自上下文。坐标是否必要通过 A/B 决定，无须同时塞入所有几何和全文。
- 精确文本对应时由程序生成候选锚点范围，降低模型手算码点的负担；不同表述仍交给模型判断并保留歧义。
- 输入改造需同时更新 Prompt 合同、旧内置值迁移和预览，自定义内容保持。不能只改提示词文案而不改运行时载荷。

验收：重复词位置选择正确率、完整词组率、错词目标率、零建议正确率，以及每页人工复核数量。

## 4. 勾画：连续性之外，还需要语义和真实空间校验

### 本轮可复现探针

| 输入 | 当前结果 | 缺口 |
| --- | --- | --- |
| 讲稿“核心概念”，连续选择画面“关键结论”，模型输出 ambiguous=false | 一条 spatial=valid | 只校验讲稿切片和候选 ID，没有独立验证画面文本是否对应 |
| OCR 顺序相邻的“核心”字框相距 800px | 一条 spatial=valid | 阅读顺序连续不保证同一视觉短语 |
| 候选带 chars_changed=true，模型未标歧义 | 一条 spatial=valid | 校验层未直接使用该边界风险 |

刚完成的连续性规则有效拦截“完/画”等跳字，不能把它解释为完整的语义质量检查。也不应要求所有画面词与讲稿完全相同，否则近义解释、数字口语化都会被误杀。

### 建议

- 将阅读顺序、行内相邻字间距、列/卡片边界一起用于空间校验。跨行只在确实连续的换行短语中允许，不能因为列表相邻就跨卡片拼接。
- 用确定性规则识别明显文本不对应，再对合理同义、OCR 错字、数字写法分别处理，避免全部合成一个 ambiguous。
- 纠正导致字数/字符边界改变时需要重新定位或复核，不能沿用旧字框却当作新的精确字符。
- 画面目标文本与讲稿锚点文本分开保存/展示，避免用讲稿 quote 冒充原图实际词语。

验收：选中目标的实际文本、对应位置和边界都正确；模型未自报歧义时程序仍能阻止已知高风险结果。

## 5. OCR：针对风险区域做含位置高精度复识别

当前 `annotation_ocr_baidu.py:54` 使用通用含位置接口 `/ocr/v1/general`。真实横屏中“概”曾识别为“慨”，竖屏相同词则正确。单次错字不能证明整套引擎差，也不适合用讲稿把画面文字一律改成预期值。

建议保留普通 OCR 快路径，对重点短语不一致、缺字、小字、数字单位等风险区使用原始高分辨率裁剪进行高精度复识别，候选框需完整记录 ROI/缩放反变换。保留两份识别及来源，不静默覆盖原始文字；字符粒度必须来自真实引擎，不均分行框造字框。

应选“含位置高精度版”能力，验证真实 char 框输出，不能只换成仅返回文本的接口。百度官方文档说明该含位置高精度能力支持更高精度，但耗时更长；本地能否改善、增加多少调用需单独测试。[官方接口文档](https://ai.baidu.com/ai-doc/OCR/tk3h7y2aq)

验收：目标词字符错误率、数字/单位完全正确率、字框定位误差、二次识别触发率及耗时。供应商概率不能直接当准确率，字/行级概率也不能替代空间核验。

## 6. 音频：区分模型边界、成片传输、第一可见笔迹

当前实现对音频/讲稿哈希、原文范围、时间正区间、顺序、异常字符时长、SDK 修补区间已有校验，方向正确。但这些是结构保护，不能证明发音起点正确。

历史 Qwen 24 条独立对照记录为 19/24 在 150ms 内、中位 81ms、P95 235ms、最大 822ms；当前这批历史音频/标签不在本机对应目录，未重新计算。这是历史证据，不是本轮新验收。另一个旧引擎的局部重对齐试验反而从 16/24 降到 15/24，不能据此将“裁短窗口”当作必然有效方案。

最近两条真实音频的 26.7ms/6.7ms 是 30fps 调度量化误差；42.6875ms 是成片与原始音频的互相关偏移；扣除该偏移后的第一可见笔迹差约 50.6ms/30.6ms。它们均以模型时间为参照，不等于与人工发音起点的误差。

建议先保留固定 Qwen 版本。对停顿、重复词、数字金额/单位、英文、语速变化建立独立集，再比较候选方案。必要的风险处理可以检查锚点落在明显长静音、字词间异常间隙、不同定位结果分歧，但不能按音量阈值一律移到最近峰值；轻声和送气音未必有大能量峰。绝不根据少量样本统一提前/延后所有标注。

完整误差链：人工真实发音 → 模型估计 → 帧调度 → 编解码音轨偏移 → 第一可见笔迹。分别记录后再决定优化哪一段，不能把同一误差加两次或用提高 fps 掩盖模型误差。[Qwen 官方模型能力](https://huggingface.co/Qwen/Qwen3-ForcedAligner-0.6B)

人工验收暂缓期间可做结构和同步工程检查，但无法可信给出新的声学 P95。不得拿模型互相同意当成人工真值。

## 7. 轨迹和 Mask 联动：检查真正可见的笔迹边界

`annotation_geometry.py:365` 的 highlighter 没有使用 Fragment 的左右邻词留白，圆圈和下划线有对应分支。探针给 highlighter 设置 0 左右留白与默认结果完全一致。AI 推荐实际统一生成 highlighter，因此此分支比只优化圆圈更值得检查。该证据说明边界约束未被消费，不等于已证明所有页面都会串字。

建议对最终透明笔迹 raster 做邻词/邻行侵入检测，区分线条中心、笔宽、端帽和抗锯齿，空间不足时限制外扩。不能靠降低透明度掩盖覆盖错误。字体较小、密排日期/金额、跨行短语应进入单独样本。

现有 `annotation_build.target_ready_times` 已按实际 Reveal 层 alpha 检查目标就绪，不应退回“只检查 bbox”。仍需动态 Mask 回归确保目标完整出现后再勾画；不通过偷偷推迟笔迹掩盖讲稿和 Reveal 时序冲突。

## 执行优先级

| 批次 | 工作 | 收益 | 完成判据 |
| --- | --- | --- | --- |
| 第一批 | Mask 标题/版式规则；完整短语候选与必要上下文；勾画语义/空间后验校验 | 减少错组、错词和无效复核 | 固定失败样例修复；未见留出集无明显回退；记录误拒绝和人工修正时间 |
| 第二批 | 风险区域 OCR 高精度复识别；Mask 冲突对象有界复核；highlighter 边界 | 减少 OCR 错字、大片强制归属、邻词侵入 | 收益与额外调用、耗时共同报告，不靠调低门槛换通过率 |
| 第三批 | 独立人工声学验收恢复后，优化语音文本映射/定位风险筛查 | 提升真实音频同步 | 同音频哈希独立标签，分类型 P50/P95/最大误差、不可用率、严重错位率 |

模型更换、分割器升级、通用自主 Agent 暂不作为第一步。若有界冲突复核在冻结集和新留出页上确有收益，可将其作为具体能力加入现有流程，不必先重构整套系统。

## 验收集与指标

建议使用 30–50 张新真实页作为第一轮工程样本，分开开发页和未参与调参的留出页，覆盖横竖屏、标题位置、多卡片、比较图、连线/外框、浅色内容、装饰、密排文字、重复词、数字英文和动态 Mask。这是建议的起步规模，不宣称具有统计充分性。

Mask 分别报告：检测前景覆盖、源图可见内容遗漏、跨组像素重叠、完整对象归属、关键语义组正确率、无需修正页比例。勾画分别报告：目标词/位置正确率、字框与可见笔迹边界、重复词消歧、无需复核比例。两步都记录人工每页修正耗时、调用次数和失败率。

先固定准入要求：已检测前景覆盖至少 99.5%、零跨组重叠、不丢正文；目标连续且语义对应；高风险结果不得假装已确认。声学精度继续以既定 P95≤150ms、严重差异>300ms 单列为目标，不以本次工程检查冒充达标。阈值应事前冻结并在新留出样本验证，不能修改标签或降低门槛宣布优化成功。
