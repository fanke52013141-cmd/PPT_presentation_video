# 数字人双模式开发与实测

日期：2026-11-05。两种模式已通过隔离项目的真实接口、合成和第 8 步 Remotion 导出验证。浏览器手动交互尚未验证。

## 目标与完成条件

- 可选第 7 步支持照片 + 动作视频（默认模板或自定义）以及直接上传成品视频。
- 照片模式先迁移身份与头部动作，再使用第 5 步确认音频对口型；不能以原有图片直接生成冒充动作迁移。
- 成品视频模式跳过模型生成，默认静音并使用课程旁白；检查时长，禁止无提示拉伸。
- 两种模式保留各自素材，共用圆形/矩形窗口与第 8 步合成。
- 底片按照片、动作模板、模型配置的内容指纹复用；任务失败保留上次成功结果。
- 旁白、模式、素材变化的 freshness 与影响处理在 Web 和 Agent 保持一致；相同保存为 no-op。
- 单机模型环境与权重放在外部资源目录，不提交运行数据或凭据。
- 完成针对性测试、Agent 契约同步、canonical checks、代码审查和实际 UI 验证。
- 实际生成角色 A 的至少 20 秒讲课视频（主体清晰、背景虚化），验证成品导入。
- 用 A 视频驱动不同角色 B 的照片，再对口型，交付至少 20 秒真实迁移结果；检查身份、动作、接缝和同步。

## 当前基线

- main: e94948a；原有 ComfyUI/InfiniteTalk 和成品视频上传入口可复用。
- RTX 5080，显存约 16 GB；外部资源位于 D:/PPT_Studio_Assets。
- 原有代码没有 LivePortrait + MuseTalk 动作迁移链路。
- 生成耗时与画质必须由实际运行记录，不引用其他硬件的性能作为验收。

## 实施顺序

1. 环境检查、原有链路启动、角色图片和旁白制备。
2. 部署独立动作迁移/对口型环境并验证模型 CLI，记录版本。
3. 实现 source-owned 双模式服务、输入校验、缓存与原子发布。
4. 接入 Web 和 Agent、契约、下游影响、任务恢复与 UI。
5. 隔离自动测试、两条真实视频链路、成片与页面验证。
