# 合成音频的长停顿压缩

可见第 5 步新合成的音频（包括单页重生成和一键生成）在写入正式工件前，自动将每处超过 2 秒的连续静音压缩至约 2 秒。短停顿保持原样。检测阈值为 -50 dB；本功能处理静音，不识别有声吸气。

`tts_silence_service.py` 在临时目录解码并检测波形，从长静音中间裁切，保留两侧各约 1 秒。没有符合条件的区间时，音频、字幕和元数据保持原字节；有裁切时重新编码一次 MP3，并将同一份裁剪映射应用于句级字幕及供应商提供的句级、字级时间戳。供应商字级时间戳只有在原音频哈希匹配时才重新绑定到处理后音频，不提升估算时间戳的精度。

处理发生在 beat 映射之后、临时结果提升之前。确认音频和续跑保留已压缩的时间轴。Reveal 动画在现有绑定流程中重建；现有音频变更失效流程负责更新勾画和数字人依赖，避免旧时间轴被继续使用。

剪前的四个工件保存在项目的 `recovery/audio/<slide_id>-<id>/before_silence_compression/`，被替换的上一版正式工件仍保存在同级恢复目录。任何解码、编码或时间轴校验失败都阻止该页提升，保留原正式音频并返回可重试错误。

已有缓存和已确认音频不会被后台改写。需要对旧音频应用规则时，在第 5 步重新生成对应页面、试听并确认，再重新导出视频。此功能不修改已经导出的 MP4。

## 发布验证（2026-10-23）

- 492 项相关测试通过，覆盖 Agent 契约、迁移、下游失效、音频确认、任务恢复和静音处理。
- Python 编译、可见步骤流程检查、Agent 契约生成一致性检查、Remotion TypeScript 检查通过。
- 使用单声道、双声道和 MP3 测试素材验证长静音压缩、短停顿保留、时间戳同步、无改动时字节不变和恢复备份。测试素材由音调和静音组成，实际业务音频仍需在第 5 步试听确认。
- 服务未启用代码热重载；更新代码后需重启服务加载新逻辑。
