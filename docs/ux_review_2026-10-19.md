# 用户体验评估报告（2026-10-19）

- **评估方式**：以真实用户身份在本地运行实例（127.0.0.1:8000）上完整操作：首页/项目库 → 新建项目（自动模式）→ 自动流程全程观察 → 完成态项目逐步骤走查 → 勾画工作区深度实操（AI 勾画、手动框选、讲稿关联、音频定位、同步预览、确认本页）→ 数字人 → 输出。
- **环境**：真实账号配置（LLM / 生图 / TTS / 百度 OCR 均真实调用）；完成态样本项目「# 什么是 稠密模型」（8/8 步完成、音频已确认、含历史渲染视频）。
- **测试痕迹说明**：评估中创建的测试项目已删除；在样本项目第 1 页添加的测试标注已通过 API 删除恢复（`annotations.json` items 已清空）。AI 勾画产生的 detect/plan/align/preview 任务记录与 `text_layout.json`、墨迹缓存为可重建派生物，予以保留。

---

## 一、核心结论

产品的主干体验已经成型且**手动勾画闭环（框选 → 关联讲稿 → 音频定位 → 确认）顺畅完整**，自动模式效率惊人（创建到渲染完成仅 4.5 分钟）。但当前有 **4 个阻塞性问题**会直接打断用户：

1. **同步预览假死**（勾画核心功能，实测 2/2 复现）——任务服务端已成功，界面永远停在「构建画面 10% / 检查同步 25%」，不弹预览，「停止预览准备」按钮无效。
2. **自动模式"静默烧钱"**——创建项目即自动分镜+生 5 张图+TTS+渲染，全程无成本提示、无起点确认；暂停入口藏在「一键生成视频」模态里，页面上没有常驻的停止控制。
3. **AI 勾画等待体验崩坏**——实测 AI 规划跑了 6 分钟后超时失败，期间进度恒为 5% 不动、无取消按钮；失败后（预览假死场景下）连失败提示都看不到。
4. **Step 8 输出面板状态串台**——实测同时显示「输出失败」「Remotion 渲染中（已用 47 秒）」「PPTX 生成中」「视频生成完成」四种互相矛盾的状态，其中前三项均不属于当前项目。

## 二、分旅程发现

### 2.1 首页与项目库

| # | 发现 | 严重度 | 说明 |
|---|------|--------|------|
| UX-1 | 35 个项目平铺无分组/排序，其中 25 个是 `ai-mask-benchmark-*` 内部测试项目 | 中 | 真实用户视角库被测试数据淹没；已有搜索框和左侧课程树，但缺「最近打开」排序或批量清理引导 |
| UX-2 | 创建项目成功后**零反馈、不进入项目** | 中 | 成功 toast 被全局吞掉（代码层 `showToast` 仅显示 error），弹窗关闭后停在首页，新卡片插在列表顶部但用户不知道下一步；对比：普通工具类产品创建后直接进入向导 |
| UX-3 | 新建表单的「自动模式 / 手动模式」两个词无任何说明 | 高（与 UX-5 叠加） | 新用户无法预见"自动模式=立即全自动生成并消耗额度"；表单其余部分（分区编号、时长下拉、占位提示）做得好 |
| UX-4 | 课程树里 5 个「新建课程」空壳（"暂无视频项目"） | 低 | 测试残留观感 |

### 2.2 自动模式全流程（实测时间线）

```
22:24:58 填表创建（选了默认"自动模式"+16:9+不设时长，附一段 102 字文章）
22:25:00 一键流程自动启动（用户未再点击任何按钮）
22:25:37 分镜完成（自动 LLM，5 页）
22:26:58 5 张图片生成完成（自动生图，81 秒）
22:27:05 图片确认完成；AI Mask 跳过（创作包默认未启用）
22:27~22:29 旁白 + TTS 完成
22:29:24 视频渲染完成 —— 全程 4.5 分钟，无一次人工干预
```

| # | 发现 | 严重度 | 说明 |
|---|------|--------|------|
| UX-5 | **创建即扣费，无确认点**：分镜未经过用户确认就直接生图 | 高 | 自动模式的价值主张成立（快），但用户对"什么时候开始花钱、花多少"没有任何控制点；建议创建前显示"将自动执行：分镜 → 5 张图 → TTS → 渲染"并二次确认，或在首个生图批次前设一个可关闭的确认 |
| UX-6 | **暂停入口深**：运行中页面上无常驻停止控制，需点「一键生成视频」打开模态才有「暂停生成」 | 高 | 我在 Step 3 面板全屏搜索"暂停/停止/取消"均无果；建议运行期间在工作区 header 常驻状态胶囊（当前阶段 + 暂停按钮） |
| UX-7 | 一键模态的阶段列表观感良好（编号+状态+已用时），但**步骤条高亮与真实阶段错位**：流程实际在 images 阶段时，步骤条上"旁白与音频"被标记为运行中（对应代码缺陷：阶段映射缺 annotation/digital_human 项） | 中 | 见代码审查 CR-38 |
| UX-8 | 进入新项目直接落在 Step 3（跟随一键当前阶段），但用户心智里"我还没做分镜" | 低 | 建议首次进入时给一行上下文提示"自动模式正在为您生成，当前：图片阶段" |

### 2.3 Step 3-5（图片 / Mask / 旁白音频）

界面结构完整、操作齐备（正面）：Step 3 每页卡有完成/删除/上传/AI生成+批量工具条；Step 4 有画笔/橡皮/三态预览/语义分块；Step 5 旁白逐页编辑+TTS+确认 CTA 链路清晰。此段未发现阻塞。

### 2.4 勾画工作区（重点）

**正面体验**（值得保留的骨架）：
- 三步引导文案（AI 自动勾画 → 检查画面与语音 → 确认本页）清晰；
- 手动闭环实测全程成功：框选区域 → 标注即时持久化（切页往返**不丢**）→ 讲稿中选中「稠密模型」→ 关联成功 → 「定位音频文字」完成 → 「确认本页」状态正确翻转为 confirmed/word_aligned；
- 自动保存状态（"已保存"）反馈明确；属性面板随选中上下文切换并提示"人工修改的条目不会被 AI 重规划覆盖"（信任设计好）；
- 预览准备期间有「停止预览准备」按钮（设计意图对，但见 UX-12 实测无效）。

| # | 发现 | 严重度 | 说明 |
|---|------|--------|------|
| UX-9 | **同步预览假死（2/2 复现）** | 阻塞 | 服务端 `annotation_preview` 任务两次均 succeeded，前端分别卡在「检查同步 25%」「构建画面 10%」超 1 分钟不弹窗、状态不更新；点「停止预览准备」无效果；重新点击「同步预览」从头再来（不复用已成功任务，重复消耗渲染资源）。这是勾画"检查时机"环节的核心工具，坏了之后用户只能盲确认 |
| UX-10 | **AI 勾画等待体验**：detect 2 秒完成 → plan 阶段进度恒为「AI 生成重点中 · 5%」，实测 6 分钟后失败（LLM 两次超时） | 高 | 三重问题：① 进度数字不动（一次长 LLM 调用无中间粒度），用户无法区分"在跑"与"卡死"；② 无取消按钮；③ 失败依赖轮询终态呈现，若状态条故障（如 UX-9 场景）用户连失败都不知道。建议：LLM 调用期间改用不定态动画+已用时（比假的 5% 诚实），提供取消，plan 失败 toast 明确"已有标注已保留" |
| UX-11 | 文字候选为**单字粒度**（稠/密/模/型/是/大…逐字 chip） | 中 | 用户想标注"稠密模型"需点 4 个字（或改用框选）；若 OCR 支持词级/行级合并候选，点选效率会大幅提升 |
| UX-12 | 预览任务的状态条在确认本页后仍残留「构建画面 10%」 | 低 | 状态残留未随确认动作清理 |
| UX-13 | 「确认本页」按钮 disabled 时无原因提示（title 为空） | 低 | 就绪条件（需保存+预览+音频定位）不透明，建议 disabled 时 tooltip 列出缺什么 |

## 三、优化建议（按优先级）

**P0 —— 解除阻塞**
1. 修复同步预览假死（服务端成功→前端不呈现；连带修复「停止预览准备」无效、重试不复用）——对应代码 CR-19/20/24 区域。
2. 自动模式加成本确认点：创建前明确列出将自动执行的阶段与预计消耗；运行中在工作区常驻「当前阶段 + 暂停」胶囊。
3. 修复 Step 8 跨项目状态串台 + 「输出失败」误报。
4. AI 勾画等待改造：真实进度或诚实的"进行中+已用时"动画、可取消、失败 toast。

**P1 —— 显著提效**
5. 文字候选从单字升级为词级/行级合并候选；支持拖选多字成组。
6. 创建项目成功后自动进入项目（或给出"进入项目"的成功反馈卡）。
7. 新建表单中「自动/手动模式」加一句话说明+示例（"自动：创建后一键生成全部素材并渲染；手动：每步自己确认"）。
8. 「确认本页」等 gated 按钮 disabled 时 tooltip 说明就绪条件。
9. 首页库增加「最近打开」排序、回收站/归档，清理 benchmark 类测试项目的干扰。

**P2 —— 打磨**
10. 离场保护推广（beforeunload + 切项目 flush）到 Step 1/2/5/6。
11. 数字人/输出的错误信息文案人性化（错误卡片+重试入口，替代日志路径提示）。
12. 一键模态阶段与步骤条高亮对齐（含勾画/数字人阶段）。
13. 「历史版本 · 状态未知」等中间态补齐真实状态。
